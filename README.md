# Mini CRM для заявок агентства

Заявки в агентство приходят отовсюду: кто-то пишет боту, кто-то сразу менеджеру в личку, кто-то звонит. Эта маленькая CRM собирает всё в один список:

- **Telegram-бот** расспрашивает клиента (имя, контакт, что нужно) и сам заводит лида;
- **ваш обычный Telegram** подключается к CRM, и каждый новый собеседник в личке становится лидом;
- **вручную** можно добавить лида со звонка или встречи;
- **теги** помогают разложить лидов по полочкам и быстро найти нужных.

Новые заявки появляются в списке сами, без перезагрузки страницы.

## Запуск за пару минут

Понадобится Docker.

```bash
cp .env.example .env     # открыть и заполнить (что куда — ниже)
docker compose up -d --build
```

Откройте http://localhost:8000 и войдите с логином и паролем из `.env`. Если порт 8000 занят, укажите другой: `APP_PORT=8010 docker compose up -d`.

База данных и сессия Telegram хранятся в Docker-томе, так что перезапуск ничего не сотрёт. Миграции применяются сами при старте.

Хотите посмотреть на заполненную CRM — добавьте демо-лидов:

```bash
docker compose exec app python -m scripts.seed           # 40 выдуманных лидов и теги
docker compose exec app python -m scripts.seed --reset   # стереть лидов и теги, заполнить заново
```

## Что вписать в `.env`

Обязательно:

- `ADMIN_USERNAME`, `ADMIN_PASSWORD` — вход в CRM;
- `SECRET_KEY` — любая длинная случайная строка, например из `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

Для бота:

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather): отправьте ему `/newbot`, придумайте имя и username (на конце `bot`), и он пришлёт токен вида `123456789:AA...`.

Для личного аккаунта:

- `TG_API_ID`, `TG_API_HASH` — ключи с [my.telegram.org](https://my.telegram.org): войдите по номеру телефона, откройте **API development tools**, заполните форму (название любое, URL можно оставить пустым, платформа Desktop) и скопируйте **App api_id** и **App api_hash**.

Если какой-то из ключей не заполнен, соответствующая интеграция просто выключится, а остальная CRM продолжит работать.

Остальные настройки можно не трогать — они описаны прямо в `.env.example`. Самые полезные:

- `REOPEN_POLICY` — что делать, когда человек пишет снова, а его прошлую заявку уже закрыли: `new_lead` заведёт нового лида, `append` переоткроет старого;
- `TG_IGNORE_CONTACTS=true` — не превращать в лидов людей из ваших контактов (удобно, если подключаете личный аккаунт);
- `DATABASE_URL` — по умолчанию SQLite; для PostgreSQL укажите `postgresql+asyncpg://crm:crm@db:5432/crm` и запускайте `docker compose --profile postgres up -d`.

`.env` и папка `data/` не попадают ни в git, ни в Docker-образ — секреты остаются у вас.

## Как этим пользоваться

**Бот.** Клиент пишет `/start`, отвечает на три вопроса (номер можно отправить одной кнопкой), проверяет сводку и жмёт «Отправить». В CRM появляется лид, а клиент получает «Заявка принята!». Если тот же человек оставит заявку ещё раз, дубля не будет: она добавится в историю его лида.

**Личный Telegram.** Откройте в CRM «Подключение Telegram», введите номер, код из Telegram и, если есть, облачный пароль. Готово: теперь каждый, кто впервые напишет вам в личку, становится лидом, а следующие сообщения и ваши ответы складываются в его историю. Группы, каналы, боты и служебные уведомления в CRM не попадают. Входить заново после перезапуска не нужно, а сообщения, пришедшие пока CRM была выключена, подтянутся сами. Кнопка «Отключить» завершает сессию.

На этой же странице видно, живы ли бот и аккаунт, и если что-то пошло не так — какая была ошибка.

**Лиды.** Список с поиском, фильтрами по источнику, статусу и тегам. В карточке — все данные, теги, переписка и заметки. Статусы: новый, в работе, готово, отказ.

**Теги.** Создаются на странице «Теги», вешаются кнопкой ✎ прямо в списке или в карточке. Клик по тегу открывает всех лидов с ним, и такую ссылку можно сохранить: `/leads?tag=vip`, или сразу несколько — `/leads?tag=vip&tag=горячий`.

## Показать CRM снаружи

Чтобы дать кому-то ссылку на CRM без своего сервера, есть временный HTTPS-туннель Cloudflare:

```bash
docker compose --profile tunnel up -d
docker compose logs tunnel | grep -o 'https://[a-z0-9-]*\.trycloudflare\.com'
```

Ссылка работает, пока включён компьютер, и меняется после перезапуска туннеля. Перед этим поставьте в `.env` надёжный пароль и `SESSION_HTTPS_ONLY=true`. После пяти неверных паролей подряд вход с того же адреса блокируется на пять минут.

## Как устроено

FastAPI + SQLAlchemy (SQLite или PostgreSQL), бот на aiogram 3, личный аккаунт на Telethon, интерфейс — шаблоны Jinja2 с HTMX и Pico.css, без фронтенд-сборки.

```
app/
  services/leads.py   вся логика лидов: создание, дубли, теги, фильтры
  bot/                диалог бота и его запуск
  tg_account/         вход в личный аккаунт и обработка сообщений
  web/                страницы и шаблоны
migrations/           схема БД (Alembic)
scripts/seed.py       демо-данные
tests/                тесты (pytest)
```

Несколько решений, которые стоит знать:

- **Всё в одном процессе.** Вход в личный аккаунт идёт в несколько шагов (номер, код, пароль), и все шаги должны попасть в один и тот же клиент Telegram — поэтому бот и аккаунт живут рядом с веб-приложением. Поэтому же сервер запускается с одним воркером. Сбои Telegram не роняют CRM: интеграции сами переподключаются, а сломанная сессия просто просит войти заново.
- **Дубли отсекает база.** У одного человека в каждом источнике может быть только один открытый лид — это гарантирует уникальный индекс, так что дубль не проскочит, даже если два сообщения придут одновременно. Один и тот же человек через бота и через личку — это два разных лида.
- **Логи** — в `docker compose logs -f app`: новые лиды, входы, ошибки и переподключения Telegram.
